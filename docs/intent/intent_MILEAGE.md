# Grill Me: интервью по intent MILEAGE

- Задача: «добавить в расчёт решения по заявке проверку — пробег авто не больше 400 000 км, иначе решение review»
- Режим: Grill Me — вопросы по одному, только влияющие на реализацию
- Дата: 2026-09-27 · Сверка: `docs/setup/code_map.md`, `docs/plan/plan_MILEAGE.md`, `backend/config/rules.php`, `backend/src/Domain/DecisionEngine.php`, `backend/src/Domain/ApplicationValidator.php`

## Не спрашивал, потому что уже зафиксировано в плане/карте

- Граница 400 000 включительна: 400 000 — ок, 400 001 → review (зашито в тесты плана).
- Порог — новый ключ в `rules.php` (например `review_above_mileage_km => 400000`), не хардкод.
- Решение сейчас зависит только от LTV; пробег в `DecisionEngine` не входит.
- Пересчёт старых заявок не делаем, миграции БД и правки frontend не нужны.

## Вопрос 1. Приоритет с LTV (пробег 400 001+ и LTV > 85 %)

**Спрошено:** пробег 400 001+ км и одновременно LTV > 85 % (зона reject по LTV) — какое решение должен возвращать сервис?

**Ответ:** review перекрывает reject.

**Следствие:** любой пробег 400 001+ даёт review, даже если по LTV был бы reject. Совпадает с текущим планом и его тестом «400 001 при LTV 95 %».

## Вопрос 2. Пробег не указан

**Спрошено:** что делать, если пробег не указан (поле отсутствует, null или пустая строка)? Сейчас отсутствие/null дают 422, но пустая строка `''` молча превращается в 0 км и проходит валидацию.

**Ответ:** неизвестно → review.

**Следствие (расходится с планом):** шаг 6 плана («пустая строка → 422») отменяется; вместо ужесточения валидатора правилу нужно третье состояние «пробег неизвестен». Валидатор перестаёт отклонять заявку без пробега и передаёт признак «неизвестно» в правило.

## Вопрос 3. Валидационная граница 500 000

**Спрошено:** `max_mileage_km` = 500 000 (500 001+ сейчас → 422) — оставляем или выравниваем с новым порогом? От ответа зависит, действует ли «иначе review» для любого пробега свыше 400 000.

**Ответ:** не знаю, это надо обсудить с руководством.

**Следствие:** открытый вопрос. В плане по умолчанию — оставить 500 000 (окно 400 001–500 000 → review, 500 001+ → 422). В intent фиксируется как открытый пункт для руководства.

## Вопрос 4. Причина review в ответе API

**Спрошено:** включать ли в scope MILEAGE поле «причина review» в ответе `/api/ltv` и `/api/applications`? План упоминает его дважды с разным знаком (в «Не входит» и в открытых вопросах).

**Ответ:** включить.

**Следствие (расходится с планом):** пункт «поле "причина review"» переносится из «Не входит» в работы; контракт API и тесты расширяются (затрагивает контроллер).

## Итог

Зафиксировано решениями:

1. Пробег 400 001+ перекрывает любое решение по LTV, включая reject → `review`.
2. Пробег не указан → «неизвестно» → `review`, не 422.
3. Причина review включается в ответ API.

Открытый вопрос для руководства:

- Граница 500 000: оставить (окно 400 001–500 000 → review, 500 001+ → 422 — позиция плана по умолчанию) или выровнять с порогом 400 000 (любой пробег выше → review).

Без вопросов взято из плана/карты: 400 000 включительно; порог в `rules.php`; правило только на новые заявки; без миграций и правок frontend.

`docs/intent/intent_MILEAGE.md` не создан — ожидается ответ по границе 500 000 либо отдельная команда.
